- **按天聚合** 标签（原「每小时」）：由分钟级原始数据按天聚合，**组距可调**——直接在组距框里输入 1–365 的任意天数后回车或点「绘图」（如 7 天=按周看、30 天=按月看；**1 天即原「每日」图**；下拉候选列表已删除，超范围会自动收敛并提示）。横轴标出每点的**起始日期**，悬停数据点看该组**覆盖的日期范围**与数值；左右两侧纵轴刻度始终固定显示。
- **按分钟聚合** 标签（原「详细图」）：进入后**默认按 1 分钟**绘图并显示**最右侧（最近的数据）**，向左滚动查看更早的数据；**左右两侧纵轴刻度始终固定显示**（左轴=字、右轴=键），滚动到任何位置都看得到。**横轴标注日期**：日期画在每天 **0:00 数据点的正下方**（标出该点以右当天数据的日期），时刻刻度按屏幕空间自动稀疏、**任何组距都不重叠**；滚动后看不到 0:00 时，当前日期**固定显示在左下角（左侧纵轴下方）**。顶部组距框可**调整组距**（直接在框里输入 1–1440 的任意整数后回车或点「绘图」；下拉候选列表已删除）——输入 1 最细、1440 最粗（一天一个点）能看更长历史；超出 1–1440 会自动收敛并提示。每次切换组距/标签页后都自动回到最右侧。

  2026-10-24 按要求删除，连同计算代码）。

  「上屏字数」与「按键次数」两份值，切过去再切回来数值原样恢复，互不覆盖）。
  「按分钟聚合」「按天聚合」标签行尾部显示**当前组距下有记录以来的最高字/键及对应记录时间**。

| `input_count_raw.txt`（旧） | 分钟（旧版单文件） | 升级前的全部分钟数据都在这里；升级后第一次运行图表会自动按月拆进 `input_count_raw\`，本文件改名 `input_count_raw.txt.bak` 留底。生成器**新旧都读**，先换 lua 或先迁移都不会丢数据 |

| `keylog_ts\20260101.txt` | **按键时间戳（每天一个，2026-10-19 起）** | 每个按键事件一行 `HHMMSSmmm`（时分秒毫秒，9 字节，不含日期=文件名即日期）；换行 1 字节 LF，**每事件合计 10 字节**；只存时间戳不存按键内容，与 `keylog\` 的第 N 个键一一对应 |
| `settings.yaml` | 功能开关（非 Rime 配置） | `keylog_timestamp: true/false` 控制按键时间戳记录；保存后约 5 秒生效、无需重新部署 |
| `keylog_copies\*.txt` | 双击产生的副本 | 与对应 txt 相同、但删掉了对应行之前的内容（首行=对应行）；每次双击后清空重建 |

- **分钟级是原始数据**，小时/日都是从它聚合出来的，所以三档天然对齐。
- 每分钟的新增量先记到 `input_count_raw.tmp`（临时流水），**跨分钟时把整分钟聚合成一行**写进**当月**的
  `input_count_raw\YYYYMM.txt`，再清空临时文件。这样文件里**每个时间戳只出现一次**、不冗余；
  每月一个文件，不会越写越大（打开/备份都更快）。
- 主文件是 append-only，写入开销恒定，数据量再大也不会越写越慢（见下）。
- 打字时按键数按分钟累加、上屏字数在每次上屏时按分钟累加。触发键 `ii` 本身不计入按键统计。

### 统计口径（重要，解释「弹窗 vs 图表」为何曾不一致）

- **字数** = 每次上屏的字符数（中文/英文/标点都算）。
- **按键数** = 拼音字母键的累计（退格/空格/翻页/标点/西文模式不计）。
- **按键明细（`keylog\`）** = 每一个按键原样记录（含退格/空格/回车等），与「按键数」口径不同。
- **按键时间戳（`keylog_ts\`）** = 与按键明细**一一对应**的原始时间戳：`keylog\` 里第 N 个键 ↔
  `keylog_ts\` 第 N 行（`HHMMSSmmm`，精确到毫秒；只记按下、不记抬起，与按键明细同口径）。
  由 `settings.yaml` 的 `keylog_timestamp` 开/关（缺省开启）。
  **2026-10-19 起的新记录形式**（此前的旧记录保持原样，同一文件里两种记法并存属正常）：
  - 字母记**小写字母**（`a`–`z`，按住 Shift / 大写锁定也记小写）；数字记**数字**（`0`–`9`）；
    符号记**键帽下排的基础符号**（`,` `.` `/` `;` `'` `-` `=` `[` `]` `` ` `` `\`，即 Shift+; 也记 `;`）；
    **空格直接记一个真实空格字符**（不写「space」之类的名称）。
  - 功能键记**大写简称**（不记全称、也不过分简短）：
    `BACK`(退格) `ENTER`(回车) `ESC` `TAB` `CAPS` `SHIFT` `CTRL` `ALT` `WIN` `FN`
    `DEL` `INS` `HOME` `END` `PGUP` `PGDN` `NUM` `PRTSC` `SCRLOCK` `PAUSE` `MENU`，`F1`…`F24` 原样；
    方向键记 `↑ ↓ ← →`。
  - 组合键记「修饰键简称 + 键」：`CTRL+c`、`ALT+TAB`、`CTRL+SHIFT+ESC`；字符键配合 Shift 时不写
    SHIFT（已归一化进字符本身，Shift+a 记 `a`）。
  - 无名按键记 **`UNK`**（旧记法写作 `0x0000`，见文末问答）。
  - **旧记法**（2026-10-19 之前）：BS=退格、CR=回车、SH=Shift、CT=Ctrl、AL=Alt、WN=Win、
    HM/ED=Home/End、PU/PD=翻页、DL=Delete、IS=Insert，Shift+字母记大写字母，组合键如 `CT+c`。
- **日汇总 = `input_count.txt` 的 `day=` 行 = 与 `ii` 弹窗完全一致**（弹窗读的就是这个值）。卡片的「今日 / 记录天数 / 日均…」与每日明细表都以它为准。
- **按天聚合 / 按分钟聚合尺度 = `input_count_raw.txt` 聚合**。这是细粒度原始数据，但它**只从开始记录分钟级之后才有**；更早的输入（当天开始记录之前打的字）不体现在这两个尺度。所以「今天」这一天，这两个尺度加起来可能少于每日——这是数据记录起点造成的，往后每天都对齐。
- 历史 bug 已修：早先图表误用分钟级原始覆盖了每日汇总，导致「今日」显示得比弹窗少。现在**每日以汇总为准**，两边一致。

## 四、万一不生效

1. **打字没数据**：确认小狼毫用户目录是 `D:\MiniPrograms\RimeData`（注册表 `HKCU\SOFTWARE\Rime\Weasel\RimeUserDir`）；右键托盘→「重新部署」；必须中文模式上屏。
2. **`ii` 没反应**：重新部署；查 `build\luna_pinyin_simp.schema.yaml` 含 `lua_translator@*input_count`；极旧 librime 可把 `@*input_count` 改 `@input_count`。
3. **图表小时/分钟标签为空**：说明 `input_count_raw.txt` 还没数据——从本次更新起打字才会写分钟级；旧的只有日汇总。打几个字再刷新即可。
4. **改了 lua 想生效**：图表生成不用部署；但 **lua 逻辑改动需要重启 WeaselServer**（或重新部署）才会重新加载。
5. **按键明细没有**：确认 `keylog\` 里有没有今天的 `YYYYMMDD.txt`；没有就是 `lua/keylog.lua`
   没加载（重新部署一次），或打字走的不是小狼毫。
6. **图表提示「按键明细服务未运行」**：用 `查看每日统计.bat` 打开图表（它会后台启动
   `keylog_helper.py`）；或手动运行 `python keylog_helper.py`。直接双击 HTML 打开时该提示属正常。
   小服务只监听 127.0.0.1、8 小时无动作自动退出，任务管理器里结束 `pythonw.exe` 也可随时关掉。
7. 手动重新部署：托盘右键→「重新部署」，或 `WeaselDeployer.exe /deploy`（工作目录=安装目录）。
8. **按键时间戳（`keylog_ts\`）没有**：先看 `settings.yaml` 里 `keylog_timestamp` 是否为 `true`
   （保存后约 5 秒生效，无需重新部署）；再看 `keylog\` 有没有数据——有 `keylog\` 没 `keylog_ts\`
   一般就是开关关着。开启后**第一次打字会多等最多约 1 秒**（毫秒相位校准，每进程一次，之后不再发生）。

## 六、常见问答

**Q：`build_svg` 输出里的 `xmlns="http://www.w3.org/2000/svg"` 是干嘛用的？如果 w3.org 这台服务器不存在了，程序还能用吗？**

A：那是 **XML 命名空间标识符**——一个固定的字符串，用来声明「`<svg>` 及其子元素属于 SVG 词汇表」，
浏览器**不会联网去访问它**，它不是资源地址（正因如此它必须保持 `http://` 而不能改成 `https://`，
改了反而不符合 HTML 规范）。图表页的 CSS、JS、数据（`window.MIN_RAW`）全部内嵌在生成的
HTML 里，字体只用系统字体，**生成与打开都不联网**，因此程序**本来就不依赖任何第三方服务器**，
无需下载任何文件。SVG 也可用 `--png` 选项输出（需 matplotlib），同样离线可用。

**Q：Python 里的 CSS 要不要单独存放？行业惯例是怎么放的？**

A：两种主流做法：①**独立资源文件**——大中型 Web 项目惯例是 `assets/style.css`、`assets/app.js`
（或模板目录）与代码分离，构建时 `<link>` 引用或内联进产物；②**生成器内嵌**——像本项目这样
「生成自包含 HTML 报表」的小工具，把 CSS/JS 作为字符串内嵌在生成器里同样是常见惯例
（pytest-html、coverage.py 等报告生成器都把资源打进产物），好处是**单文件、零依赖、
生成的 HTML 可随意拷贝**。鉴于本程序要求完全离线、输出必须自包含，**维持内嵌即可**；
若以后样式体量继续变大，可拆成 `chart.css` / `chart.js` 两个文件、生成时读入再内联进 HTML，
输出形态不变、只是源码组织更清晰。

**Q：`keylog_ts\` 里每行的毫秒是从哪来的？为什么开启后的第一次打字会顿一下？**

A：毫秒取自 `os.clock()`——小狼毫的 Lua 随 `rime.dll` 以 MSVC 编译，Windows CRT 的 `clock()` 是
**「进程启动以来的墙钟时间」、精度 1 毫秒**（Microsoft 文档明述；本机已实测校验）。Lua 标准库只有
秒级的 `os.time()`、拿不到「现在是这一秒的第几毫秒」，所以写第一条时间戳前会**等一次秒进位的瞬间**
来校准毫秒相位——每进程一次、最多约 1 秒，就是开启功能后第一次打字会多等的那一下，之后不再发生。
另有「懒校验」用两次按键之间 `os.clock()` 与墙钟各自的前进量确认 `clock()` 确实是墙钟语义；万一
遇到 CPU 时间语义（非 MSVC 的罕见环境），毫秒位自动退化为 `000`、绝不写错数据。最终每行
`HHMMSSmmm` 都是真实的时分秒毫秒，且与 `keylog\` 的键一一对应，可直接拿去做按键间隔分析。

**Q：`keylog_ts\` 一行为什么是 9 个数字、连冒号都没有？**

A：格式是 `HHMMSSmmm`——时(2) 分(2) 秒(2) 毫秒(3)，定长、一眼能认；省掉冒号和日期正是为了
「占用字节越少越好」：不含日期（文件名就是当天日期），换行只写 1 字节 LF，**每个按键事件合计 10 字节**。
解析时按定长切片即可（`line[:2]` 时、`line[2:4]` 分、`line[4:6]` 秒、`line[6:9]` 毫秒）。

**Q：`keylog\` 里大量出现的 `0x0000`（新记法记作 `UNK`）到底是什么键？系统自己知道吗？是程序读不到名字吗？**

A：这不是某个键的「名字」，而是**事件本身没有携带键名**。按键事件传到输入法引擎（librime）这一层时
只剩一个「键符编号」，`0x0000` 就是编号 0 —— X11 键符表里的 `NoSymbol`，`key:repr()` 查不到名字
只能原样输出十六进制。它的来源一般是 **Fn 键、笔记本多媒体/亮度热键、修饰键抬起/状态变化**这类
不产生标准键名的事件（所以它们常成对、成串出现）。
**不是程序偷懒没查名字**：系统底层（键盘驱动/Windows）知道你按了什么（有扫描码/VK 码），
但那个原始编号在 Windows → Rime 的转换环节没有对应键符，名字在到达 lua 之前就丢了；
`key:repr()` 已经是 librime-lua 能提供的全部信息。所以 2026-10-19 起统一记作 `UNK`（3 个字符、
可读、不再刷屏 6 个字符的十六进制）。若想知道它究竟对应哪个物理键，要在**更底层**抓
（低层键盘钩子 / AutoHotkey 能看到原始 VK 码）——这正是「只记录电脑返回的最初始的值」的完全体方案，
详见 `优化建议.md`。
